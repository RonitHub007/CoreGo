📘 Understanding Maps in Go (Internals & Usage)

Maps in Go provide an efficient way to store and retrieve key–value pairs. They were introduced to handle situations where sequential data structures like slices and arrays become inefficient for key-based lookups.

🔹 Map Basics

Syntax:

map[keyType]valueType


Maps are reference types in Go.

If a map is declared but not initialized, it is nil.

Example
var nilMap map[string]int
fmt.Println(nilMap == nil) // true

// Accessing or writing to a nil map causes a runtime panic:
nilMap["key"] = 42 // panic: assignment to entry in nil map

🔹 Internal Structure of Maps in Go

Internally, a Go map has a map header and a set of buckets.

                        map header
                    ________________ 
 m --------------->| len            |  // number of elements
                   |________________|               
                   | lg(#buckets)   |  // number of buckets
                   |________________|                
                   | bucket array   |  // points to buckets
                   |________________|                
                   | hash seed      |  // randomized for security
                   | . . .          |
                   |________________|


Buckets: Each element in the array is called a bucket.

Hashing: Go uses an internal hash function to place keys into buckets.

Lookup operations (mapaccess1 / mapaccess2 at runtime) use O(1) average time complexity.

🔹 Map Lookup & The comma, ok Idiom

When accessing a key, you may not always know if it exists.
Go provides a safe way to check:

scores := map[string]int{"Alice": 90, "Bob": 80}

value := scores["Charlie"]          // returns 0 (default int value)
value, ok := scores["Charlie"]      // returns 0, false

fmt.Println(value) // 0
fmt.Println(ok)    // false


👉 Key Difference:

If the key does not exist → Go returns the zero value of the type (e.g., 0 for int).

To distinguish between "key not present" and "key has a zero value", use the comma, ok idiom.

🔹 Using Maps as Sets

Go does not have a built-in set type. However, maps can be used to implement sets:

Set := map[int]bool{}

Slice := []int{1, 2, 3, 4, 5, 4, 5, 6, 2, 3, 7}

for _, value := range Slice {
	Set[value] = true
}

fmt.Println("Slice length:", len(Slice), Slice)
fmt.Println("Set length:", len(Set), Set)


Output:

Slice length: 10 [1 2 3 4 5 4 5 6 2 3 7]
Set length: 7 map[1:true 2:true 3:true 4:true 5:true 6:true 7:true]


✅ The map automatically removes duplicates, making it behave like a set.

✅ Summary

Maps in Go are hash-based key–value stores.

A nil map exists but cannot be used for inserts (will panic).

Internally, Go uses buckets and a hash function for efficient lookup.

The comma, ok idiom helps differentiate between missing keys and zero values.

Maps can also be used to implement sets, since Go has no built-in set type.
