    Rune vs Byte 


    In Go, byte and rune are two different types for handling characters and text. The key difference is what they represent: a byte is a single, 8-bit piece of raw data, while a rune is a single Unicode code point.

Here's a breakdown:

byte: This is an alias for the uint8 data type. It represents a single 8-bit integer, ranging from 0 to 255. In the context of text, a byte can represent an ASCII character, since ASCII characters all fit within this 8-bit range. However, a byte is not inherently a character; it's a piece of raw data. A string in Go is a slice of bytes ([]byte).

rune: This is an alias for the int32 data type. It represents a single Unicode code point. This is the fundamental unit for working with characters in Go, especially when dealing with non-English or special characters (like emojis or characters from other languages). A single rune can be composed of one or more bytes when encoded in UTF-8. Because Go uses UTF-8 for its strings, a single "character" might be represented by multiple bytes. The rune type lets you work with that character as a single, consistent unit.

📘 Understanding Strings in Go
Strings in Go (string) are sequences of bytes. However, unlike some other languages, Go strings are encoded in UTF-8, which allows them to represent characters from many human languages, including special characters and emojis.

🔹 Strings in Go
A Go string is an immutable sequence of bytes ([]byte).

By default, strings are encoded using UTF-8.

Immutability: Once created, the contents of a string cannot be changed.

Slicing: When slicing a string, Go works on the underlying bytes, not on Unicode characters directly.

🔹 What is UTF-8?
UTF-8 (Unicode Transformation Format – 8-bit) is the most widely used encoding for text today. It supports:

English alphabets (ASCII compatible).

Characters from other languages (Arabic, Hindi, Chinese, etc.).

Special symbols and emojis.

How UTF-8 Works
ASCII characters (A–Z, a–z, digits, punctuation) use 1 byte.

Non-ASCII characters (e.g., é, 😊) require 2–4 bytes.

Example
A → ASCII value = 65, binary = 01000001 → 1 byte

é → Unicode code point U+00E9 → UTF-8 = 11000011 10101001 → 2 bytes

😊 → Unicode code point U+1F60A → UTF-8 = 11110000 10011111 10011000 10101010 → 4 bytes

🔹 Example: String Slicing in Go
package main

import "fmt"

func main() {
    s := "Hello 😊"
    s2 := s[4:7]
    s3 := s[:5]
    s4 := s[6:]

    fmt.Println("s2:", s2)
    fmt.Println("s3:", s3)
    fmt.Println("s4:", s4)
}
Indexing Breakdown
H => 0
e => 1
l => 2
l => 3
o => 4
(space) => 5
😊 => 6 (BUT actually stored as 4 bytes!)
Output Explanation
s2 := s[4:7] → "o �"

Why? Because 😊 is 4 bytes long. The slice takes only the first byte of the emoji, leading to an invalid partial UTF-8 sequence (�).

s3 := s[:5] → "Hello"

Clean slice up to index 5 (works fine since all are single-byte characters).

s4 := s[6:] → "😊"

Starts exactly at the first byte of the emoji, so UTF-8 decoder correctly reads the entire 4-byte sequence.

⚠️ Twist: Even though len(s) appears to be 7 characters, Go counts bytes, not runes.

fmt.Println(len(s))      // 9 (bytes, because 😊 is 4 bytes)
fmt.Println([]rune(s))   // [72 101 108 108 111 32 128522] (7 runes)
🔹 Rune vs Byte in Go
byte
Alias for uint8 (0–255).

Represents raw 8-bit data.

Suitable for ASCII characters.

A string in Go is actually a slice of bytes ([]byte).

rune
Alias for int32.

Represents a Unicode code point.

A single rune may be 1–4 bytes in UTF-8.

Preferred when dealing with non-English characters and emojis.

Example
s := "é😊"

// Length in bytes
fmt.Println(len(s)) // 6 (é=2 bytes, 😊=4 bytes)

// Length in runes
fmt.Println(len([]rune(s))) // 2

// Iterating over runes
for i, r := range s {
    fmt.Printf("%d -> %c (Unicode: %U)\n", i, r, r)
}
Output:

0 -> é (Unicode: U+00E9)
2 -> 😊 (Unicode: U+1F60A)
✅ Summary
Go strings = UTF-8 encoded, immutable byte sequences.

Slicing works on bytes, not runes.

ASCII chars → 1 byte, Emojis → 2–4 bytes.

Use rune when working with characters, byte when working with raw data.

👉 This makes Go very efficient and Unicode-friendly, but you must be careful when slicing or indexing strings containing multi-byte characters.
